# kasb-exaone-qlora-finetune

한국 회계기준 챗봇의 로컬 모델(LG EXAONE-3.5-7.8B-Instruct)을
QLoRA로 파인튜닝해서 답변 품질(근거 충실도)을 개선하려 한 3차례 실험 기록입니다. 이후 파인튜닝 없이
프롬프트만 바꾼 대조 실험도 추가로 기록했습니다.

## 결론

**파인튜닝은 성능을 개선하지 못했습니다.** 파인튜닝 안 한 베이스 모델이 세 번의 재학습 시도보다 계속 더
나았습니다. kasb-crawler 프로덕션은 로컬 모델을 베이스(`exaone3.5:7.8b`)로 고정했고, 이 저장소는
"왜 실패했는지", "무엇을 시도했는지"를 기록해 같은 시행착오를 반복하지 않기 위한 것입니다.

추가로, 학습 없이 시스템 프롬프트에 지시 1줄만 더한 대조 실험(아래 표 참조)이 파인튜닝 3회와
원본 베이스라인을 전부 앞섰습니다 — **학습이라는 비싼 수단 없이도 더 유용한 결과가 가능하다**는
근거입니다. 자세한 내용은 아래 "프롬프트 1줄 추가" 절 참조.

## 평가 방법 (전 실험 공통)

- **held-out 30문항**: `kasb-crawler/eval/goldenset.jsonl`(전체 1195문항, 학습 데이터에서 제외된 순수 평가용)에서
  게시판별 비례 샘플링(seed=42)한 30문항. 베이스라인/v1/v2/v3와 프롬프트 실험까지 전부 동일 샘플.
- **판사**: GPT-4o-mini, 전 실험 동일 모델(비교 일관성 유지). `rag/eval/judge.py`의
  Faithfulness(답변 주장이 근거자료로 뒷받침되는 비율, 0~1) / Answer Relevancy(질문에 실제로
  답했는지, 0~1) 두 지표.
- **거부율**: 30문항 중 모델이 "근거를 찾지 못했습니다"로 답변을 포기한 비율.
- 아래 표의 Faithfulness/Answer Relevancy는 **30문항 전체 기준(거부한 문항은 0점으로 반영)**입니다 —
  "답변한 문항만"의 조건부 평균은 거부를 분모에서 빼버려 그 손실을 가려버리므로, 실제로 전달되는
  가치를 보려면 거부율까지 곱해야 합니다. 버전별 "답변한 문항만" 원점수는 [`docs/RESULTS.md`](docs/RESULTS.md)에 있습니다.
- 베이스라인의 "답변한 문항만" 원점수(Faithfulness 0.900, Answer Relevancy 0.975)는 재현성까지
  확인했습니다(같은 grounding으로 판사만 재호출 → 20/20 문항 점수 완전 동일,
  `eval/results/exaone_baseline_rejudge.jsonl` 참조).

## 결과 비교

| | 거부율 | Faithfulness(전체 30문항, 거부=0점) | Answer Relevancy(전체 30문항, 거부=0점) |
|---|---|---|---|
| 베이스라인 (파인튜닝 안 함) | 33.0% (10/30) | 0.600 | 0.650 |
| v1 (표준 SFT) | 66.7% (20/30) | 0.267 (최저) | — (원 지표 자체 미측정) |
| v2 (completion-only loss + eval_loss 체크포인트 선택) | 46.7% (14/30) | 0.400 | 0.343 (최저) |
| v3 (데이터 8개 통일 + 생성·판사 기반 체크포인트 선택) | 43.3% (13/30) | 0.450 | 0.410 |
| 베이스 + 프롬프트 1줄 추가(학습 없음, 아래 참조) | 13.3% (4/30) | 0.744 | **0.807** (최고) |
| v3 + 프롬프트 1줄 추가(파인튜닝+프롬프트 결합) | **10.0%** (3/30, 최저) | **0.750** (최고) | 0.647 |

이 기준으로도 v3는 v1·v2보다 낫지만 베이스라인은 못 넘고, 베이스·v3 둘 다 "프롬프트 1줄 추가"를
얹은 쪽이 원본보다 전부 앞섭니다.

## 버전별 실험 내용

공통 하이퍼파라미터(QLoRA 논문값, Dettmers et al. 2023)는 3버전 전부 동일하게 사용했습니다.
버전마다 실제로 바뀐 건 하이퍼파라미터가 아니라 손실 계산 범위·체크포인트 선택 방식·학습 데이터
구성입니다. 상세 수치·하이퍼파라미터표는 [`docs/RESULTS.md`](docs/RESULTS.md) 참조.

**v1 — 표준 SFT (최초 시도)**: RAFT 스타일 데이터 700건(golden+distractor 최대 3~5개)으로 표준
방식 그대로 학습. 목표는 "여러 후보 문서 중 진짜 근거를 골라 인용하는 능력"을 가르치는 것이었으나 실패했습니다 — ① LoRA 어댑터가 답변 노드뿐 아니라 질문분류·재작성 노드에도 적용돼, 이
노드들이 학습 분포 밖 입력에서 무한반복 생성에 빠짐 ② `max_length=4096` 고정이 학습 데이터 최장
예시(~14,000자)보다 짧아 정답이 중간에 잘린 채로 학습됨. 결과: 거부율 66.7%

**v2 — 구조 버그 수정 + 체크포인트 선택 정상화**: v1의 두 버그를 고치고(LoRA를 답변 노드에만 적용,
길이 동적 산출), 정답 부분만 학습 신호로 쓰는 `completion_only_loss=True`를 추가, "3 에폭 중 최적
체크포인트 선택"을 실제로 작동하게 구현(v1은 markdown에만 적혀있고 코드에는 빠져있던 버그). 그런데
결과는 v1보다 더 나빠졌습니다 — 선택 기준으로 쓴 eval_loss(다음 토큰 예측 손실)가 실제 생성 품질과
무관했을 가능성이 유력한 원인으로, LIMA 논문(Zhou et al. 2023)이 경고한 것과 정확히 같은 현상입니다.

**v3 — 생성 기반 체크포인트 선택 + 학습·실전 조건 통일**: v2의 문제(eval_loss가 실제 품질과 무관)를
고치려고, 체크포인트마다 실제로 텍스트를 생성시켜 GPT-4o-mini 판사로 채점해 최고점을 고르는 방식으로
교체했습니다. 추가로 학습 때 보여주는 근거문서 개수(3~4개)를 실전 조건(8개)과 통일 — RAFT 논문이
지적한 "연습-실전 조건 불일치"를 없앤 것입니다. v1·v2보다는 개선됐지만 여전히 베이스라인을 못
넘었고, 답변 17건 중 7건에 근거 이탈이 남아 "조건 불일치만으로는 격차가 설명되지 않는다"는
결론으로 이어졌습니다.

## 프롬프트 1줄 추가 (파인튜닝 없음)

파인튜닝 3회가 전부 베이스라인을 못 넘은 뒤, "파인튜닝 자체를 접고 프롬프트만 바꾸면 어떨까"를
가장 저비용으로 확인한 대조 실험입니다. 실제 서비스 프롬프트 끝에 지시 1개만 추가했습니다:

> "핵심 결론을 말하기 전에, 그 결론의 근거가 되는 근거 원문 문장을 [식별자] 인용과 함께 그대로
> 한 번 옮겨 적은 뒤 결론을 서술하라(원문을 바꿔 쓰지 말 것)."

출처는 RAFT 논문(Zhang et al. 2024)의 CoT+원문축어인용 포맷 — 학습데이터 생성용으로만 구현돼있던
문장을 실전 답변 프롬프트로 그대로 옮긴 것입니다. 결과(위 표): 거부율이 베이스라인의 1/3 이하로
떨어지며 파인튜닝 3회는 물론 원본 베이스라인까지 전부 앞섰습니다 — "확신 판단"이라는 애매한 과제
대신 "관련 문장을 찾아 옮겨 적기"라는 구체적 과제를 준 게 거부를 줄인 것으로 해석됩니다. v3(파인튜닝판)
에도 같은 프롬프트를 얹어봤지만(위 표 마지막 행) 프롬프트 단독판(베이스+프롬프트)을 이기지 못했습니다
— 특히 Answer Relevancy에서 뒤처져(0.647 vs 0.807), **이 문제엔 파인튜닝보다 프롬프트 설계가 더
비용 대비 효과적인 개입**이라는 근거로 남았습니다. 상세 계산은 [`docs/RESULTS.md`](docs/RESULTS.md) 참조.

재현: `eval/exaone_baseline_quotefirst_eval.py`, `eval/exaone_v3_quotefirst_eval.py`.

## 저장소 구성

```
notebooks/   Colab 학습 노트북 원본 3개(v1/v2/v3, 그대로 재실행 가능)
scripts/     노트북 빌드 스크립트(JSON 셀 surgery) + 학습데이터 생성/패치 스크립트
eval/        held-out 30문항 평가 스크립트 + 원시 결과(jsonl)
data/        실제 학습에 쓴 RAFT 스타일 데이터 (v1/v2용 700건, v3 패치본 700건)
docs/        버전별 상세 분석(하이퍼파라미터·데이터 구성·실패 원인)
```

## 재현 방법

1. `scripts/raft_data_gen_v1v2.py` (v1/v2) 또는 `data/raft_train_data_v3.jsonl`(이미 생성됨, v3)로
   학습 데이터 준비. GPT 호출이 필요한 건 v1/v2용 생성 스크립트뿐 — v3는 로컬 재검색 패치만이라
   비용 없음(`scripts/raft_data_patch_v3.py`).
2. `notebooks/v{1,2,3}_kasb_exaone_qlora_colab.ipynb`를 Google Colab에 업로드해 위에서부터 순서대로 실행.
3. 결과 GGUF를 Ollama에 배포(`ollama create`, 노트북 14단계 안내 참조) 후
   `eval/exaone_v{2,3}_final_eval.py` 또는 `exaone_baseline_eval.py`로 held-out 30문항 평가.
